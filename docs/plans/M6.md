## Context

Everything so far runs from the command line on the server. M6 puts it in a browser: upload a
3D file, see the model, the cover and the panels in 3D, change settings, run, look at the
patterns and the size drawing, and download the DXF for the cutting table. The public address
through Cloudflare needs the owner's account (question 14); until then the app is reached over
SSH:

```
ssh -L 8080:localhost:8080 dev@168.119.50.82
```

and then http://localhost:8080 on the laptop.

## First version (this step)

- **Models:** a list of all models with their status (imported, cover, panels, patterns,
  export) and warnings; upload a STEP/IGES/STL/OBJ/PLY/GLB with units and up axis; one button
  runs everything.
- **A model's page:**
  - 3D view (Three.js): the furniture, the cover (water spots in red), the panels in colour;
    switch layers on and off, turn and zoom.
  - Patterns: the flat pieces (pattern.svg), the stretch picture, the cut pieces (cut.svg).
  - The size drawing (sizes.pdf) and the cutting list, in the page.
  - Settings: every setting from `config/defaults.yaml` in its group, with its comment as help
    text, the current value and where it comes from (default, this model, trial). "Try" runs
    with the changed values without saving; "Save for this model" writes them to `cover.json`.
    After a run, what changed in the pieces (cover diff).
  - Downloads: cut.dxf, pattern.dxf, the PDFs, the GLBs.
  - Warnings and the run log.
- **Jobs:** runs go into a queue and run one at a time in the background (a big model takes
  minutes and several GB); the page shows progress per step.

Later in M6: the seam editor in the browser (click seam lines in plan view, as `seams.json`
does now), pattern revisions with diffs, and the Cloudflare deployment with login.

## Technical approach

- `apps/api` (package `coverapi`, a uv workspace member): FastAPI. Data directory
  `COVER_DATA_DIR` holds `models/<id>/` exactly as the command line writes it, so both can be
  used side by side. Jobs run the `cover` steps as subprocesses (one worker, a queue), with the
  log and step status in `jobs/<id>.json`; the web polls. Metadata lives in the model folders
  and job files (no database needed yet; SQLite when revisions and users come).
- Endpoints: `GET /api/models`, `POST /api/models` (upload), `GET /api/models/{id}`,
  `GET /api/models/{id}/files/{name}`, `GET|PUT /api/models/{id}/parameters`,
  `POST /api/models/{id}/run`, `GET /api/jobs/{id}`, `GET /api/parameters` (the registry).
- `apps/web`: React, TypeScript, Vite, Three.js. Built to static files, served by the API
  (one process, one port) so there is nothing else to run.
- `deploy/`: a Dockerfile for the app, docker compose with the app on 127.0.0.1:8080 and the
  Cloudflare tunnel as an optional profile; nightly backup of the data directory.

## Tests
